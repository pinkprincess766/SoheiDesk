# Техническое задание: SoheiDesk

**Версия:** 1.0  
**Дата:** 2026-07-21  
**Статус:** согласованный черновик  

**SoheiDesk** — самостоятельный десктопный инструмент исследователя: ридер научных и рабочих документов, аннотации, лабораторный журнал с шаблонами, библиотека литературы и экспорт в удобные форматы.

Работает **полностью автономно**. Опционально может запускать внешние приложения (например, ChromaTsvet) для открытия вложений — это не hard dependency: без них все основные сценарии доступны.

---

## 1. Цель продукта

Дать исследователю одно рабочее место, где можно:

1. Открыть и читать материалы в привычных форматах (статьи, заметки, отчёты, книги).
2. Выделять, комментировать и рисовать поверх текста, не портя исходный файл.
3. Вести лабораторный / исследовательский журнал по шаблонам (готовым или своим).
4. Собирать библиотеку документов с поиском и метаданными.
5. Экспортировать заметки, статьи и фрагменты журнала в Markdown, Typst, LaTeX, HTML, DOCX.

**Ключевой сценарий:**

> Документ → аннотации → запись в журнале (по шаблону) → экспорт отчёта / черновика статьи.

---

## 2. Принципы

| Принцип | Описание |
|--------|----------|
| Самостоятельность | Полностью автономное приложение; интеграции (Zotero, arXiv и т.д.) — опциональны |
| Не портить оригинал | Аннотации и заметки хранятся отдельно (SQLite), исходные файлы только читаются (если пользователь явно не экспортирует «плоский» файл) |
| Локальность | Данные по умолчанию на машине пользователя; облако — не обязательно |
| Форматы — first-class | PDF и TXT — не единственные; Markdown и другие текстовые форматы равноправны |
| Шаблоны — first-class | Журнал и экспорт строятся на заготовках и пользовательских шаблонах |
| Модульность | Парсеры, журнал, поиск, конвертеры, интеграции подключаются независимо |

---

## 3. Поддержка форматов

### 3.1. Вход (открытие / импорт)

| Формат | Приоритет | Примечание |
|--------|-----------|------------|
| **Markdown** (`.md`, `.markdown`) | Высокий | Нативный формат заметок и части экспорта; полноценный preview + редактирование |
| **PDF** | Высокий | Текстовый PDF; сканы — с OCR (этап позже) |
| **TXT** / **RTF** | Высокий | Простые тексты |
| **DOCX** / **ODT** | Средний | Word / LibreOffice |
| **EPUB** | Средний | Без DRM |
| **HTML** | Средний | Локальные страницы / сохранённые статьи |
| **LaTeX** (`.tex`) | Средний | Как исходник (структура + формулы), не только «готовый PDF» |

**Позиция по Markdown:**  
Markdown — не «потом», а один из основных форматов наряду с PDF. Пользователь должен комфортно открывать `.md`, читать с превью, аннотировать (где уместно), редактировать и использовать MD как промежуточный/выходной формат журнала и экспорта.

### 3.2. Выход (экспорт)

- Markdown  
- Typst  
- LaTeX  
- HTML  
- DOCX  

Экспорт применяется к: текущему документу (best-effort для PDF), заметкам/аннотациям, выбранным записям журнала, собранному отчёту.

**Ожидания по качеству конвертации:**

- Из **структурированных** источников (MD, DOCX, HTML, LaTeX source, журнал) — высокое качество.
- Из **PDF** — best-effort: текст и базовая структура; «идеальный» round-trip не гарантируется.

## 4. Функциональные требования

### 4.1. Ридер и работа с документами

- Открытие файлов из п. 3.1; drag-and-drop; недавние файлы; библиотека.
- Два режима отображения (архитектурно разделить):
  - **Page mode** — для PDF (постраничный рендер + слой аннотаций).
  - **Reflow / document mode** — для Markdown, TXT, DOCX, HTML, EPUB, LaTeX (перенос строк, оглавление, типографика).
- Навигация: оглавление (где есть), закладки, переход по страницам/заголовкам.
- Масштаб, тёмная/светлая тема, выбор шрифта (для reflow-режима).
- Поиск по открытому документу с подсветкой вхождений.

### 4.2. Аннотации и редактирование

Все аннотации хранятся **отдельно** от исходного файла (SQLite). Документ идентифицируется в первую очередь по **content_hash** (устойчивость к переименованию/переносу); путь к файлу — вторичный.

| Инструмент | Описание |
|------------|----------|
| Выделение | Цветные маркеры |
| Подчёркивание / зачёркивание | Стили текста |
| Комментарии | Привязка к фрагменту |
| Текстовые заметки | «На полях» / sticky notes |
| Рисование | Свободная рука (мышь / стилус) |
| Фигуры | Стрелки, рамки, овалы |
| Формулы | Ввод в LaTeX-синтаксисе с превью |

Аннотации можно: фильтровать, искать; экспорт списка аннотаций в MD — с этапа 2. PDF-аннотации используют page-space координаты (не CSS viewport).

### 4.3. Лабораторный журнал

Структурированный дневник исследователя.

**Запись журнала включает:**

- дату и время;
- заголовок;
- тело в **Markdown** (источник истины при хранении; редактор — MD-compatible, не «HTML как primary»);
- теги;
- вложения (файлы: спектры, картинки, таблицы, PDF и т.д. — выбор через dialog);
- ссылки на документы из библиотеки;
- поля, заданные **шаблоном** (с валидацией обязательных полей);
- снимок схемы шаблона на момент создания записи (чтобы правки шаблона не ломали старые записи).

**Поиск по журналу:** текст, дата, теги, вложения, поля шаблона.

**Экспорт журнала:** выбранные записи / период / проект → Markdown, Typst, LaTeX, HTML (отчёт для сдачи или черновик статьи).  
Перед сохранением файла — **предпросмотр** сгенерированного Markdown (MVP).

**Опционально:** вложение-спектр → «Открыть во внешнем приложении» (например, ChromaTsvet), если путь к binary настроен в настройках.

### 4.4. Шаблоны (обязательная часть продукта)

Пользователь **не обязан** каждый раз собирать запись с нуля.

#### 4.4.1. Источники шаблонов

1. **Встроенные заготовки** (поставляются с приложением), например:
   - Синтез / протокол реакции  
   - Анализ / измерение  
   - Кинетика  
   - Чтение статьи (summary + key quotes)  
   - Свободная заметка  
   - Еженедельный обзор  
2. **Пользовательские шаблоны** — создание, редактирование, дублирование, удаление, импорт/экспорт (файл шаблона, напр. JSON/YAML + Markdown body).
3. **Шаблоны на основе существующей записи** — «сохранить как шаблон».

#### 4.4.2. Что описывает шаблон

- имя, описание, иконка/категория;
- набор **полей** (текст, число, дата, список, теги, файл, ссылка на документ);
- **тело** по умолчанию (Markdown с плейсхолдерами);
- опционально: теги по умолчанию, правила экспорта (какой export-template использовать).

#### 4.4.3. Шаблоны экспорта

Отдельно от шаблонов записей:

- пресеты оформления отчёта (титул, шапка, нумерация, библиография);
- пользователь может править Typst/LaTeX/HTML/Markdown-шаблоны экспорта или добавлять свои.

### 4.5. Библиотека и поиск

- Каталог документов: метаданные (название, авторы, год, тип, теги, путь).
- Полнотекстовый поиск по библиотеке и журналу (индексация).
- Фильтры: тип, теги, дата, наличие аннотаций.
- Автосканирование папки библиотеки (опционально).

### 4.6. Интеграции (опционально, не блокер MVP)

| Источник | Назначение |
|----------|------------|
| Zotero / Mendeley | Импорт библиотеки и метаданных |
| arXiv | Поиск и скачивание препринтов |
| PubMed | Биомедицинский поиск |
| DOI / Crossref | Метаданные и BibTeX по DOI |
| RSS журналов | Лента новых публикаций |

**Экспорт цитирования:** BibTeX, RIS, APA, GOST.

Интеграции не требуются для базовой работы ридера и журнала.

### 4.7. Конвертация

- Распознавание/сохранение структуры: заголовки, списки, таблицы, формулы (где исходник это позволяет).
- Аннотации → сноски / выноски / приложение «Список выделений».
- Вложения (изображения) — вставка в отчёт с подписями.
- Библиография из метаданных библиотеки / DOI / импорта.

## 6. Архитектура (кратко)

**Десктопное приложение:** Tauri (предпочтительно) + **Rust** (бэкенд) + **Vue 3 + TypeScript** (UI).

### 6.1. Модули бэкенда (Rust)

- Парсеры форматов (PDF, MD, DOCX, EPUB, HTML, LaTeX, TXT, …)
- Индексатор / поиск (**Tantivy**)
- Аннотации и заметки (**SQLite**)
- Лабораторный журнал + **движок шаблонов**
- Конвертеры (MD, Typst, LaTeX, HTML, DOCX; pandoc — fallback)
- Интеграции (HTTP-клиенты)
- Менеджер библиотеки
- API / команды для фронтенда (IPC Tauri; при необходимости локальный HTTP)

### 6.2. Модули фронтенда (Vue 3)

- Ридер (page mode + reflow mode)
- Панель аннотаций и инструментов
- Журнал + мастер «запись из шаблона»
- Редактор шаблонов (поля + preview)
- Поиск / библиотека
- Панель интеграций
- Настройки (пути библиотеки, темы, шаблоны экспорта)

### 6.3. Хранилище (SQLite) — основные сущности

- `documents` — файлы библиотеки и метаданные  
- `annotations`, `notes`  
- `journal_entries`  
- `templates` — шаблоны записей (JSON-схема полей + body)  
- `export_templates` — шаблоны экспорта  
- `tags`  
- `integration_metadata`  
- `settings`  

Исходные файлы документов — на диске (библиотека / исходные пути); в БД — ссылки и извлечённый текст/индекс.

### 6.4. Стек (сводка)

| Слой | Технология |
|------|------------|
| Shell | Tauri |
| Backend | Rust, rusqlite, tantivy, reqwest |
| Frontend | Vue 3, TypeScript, Vite, Pinia |
| Журнал / MD | Markdown как source of truth; TipTap+MD extension или Milkdown |
| PDF | pdf.js (page mode); аннотации — page-space, отдельный слой |
| FS (MVP) | Только user-selected paths (dialog) |
| Сборка | Cargo + pnpm |

## 8. Критерии приёмки MVP

**Must (минимально shippable):**

1. Открытие PDF, TXT и `.md` через dialog, без сторонних приложений.  
2. Библиотека: после переименования файла с тем же содержимым аннотации/карточка восстанавливаются (`content_hash`).  
3. Запись журнала из **встроенного** и **своего** шаблона; тело в Markdown; required-поля валидируются.  
4. Предпросмотр и экспорт записи в Markdown-файл.  
5. Reflow-аннотации (MD/TXT) сохраняются после перезапуска.  
6. Без настроенного ChromaTsvet приложение полностью работает; с настроенным — «открыть спектр» запускает external binary.  
7. Данные (кроме исходников) локальны; standalone-сборка запускается.

**Should (полный MVP):**

8. PDF: выделение + комментарий в page-space координатах, корректно при zoom, persist/restore.

## 9. Вне скоупа (сейчас)

- Облачный SaaS и обязательная регистрация  
- Hard dependency на ChromaTsvet (допустима только optional интеграция)  
- Редактор уровня Overleaf / полный Word-клон  
- DRM-EPUB, проприетарные закрытые форматы без открытых парсеров  
- Гарантия идеальной конвертации произвольного PDF → LaTeX/Typst  
- Экспорт аннотаций в MD, OCR, full-text по библиотеке — не MVP (этап 2+)

## 10. Итог

**SoheiDesk** — самостоятельный научный ридер и рабочее место:

- **читает** широкий набор форматов, с **Markdown, PDF и TXT** в ядре с первого этапа;  
- **аннотирует** без порчи файлов (identity по content_hash);  
- **ведёт журнал** в Markdown на **готовых и пользовательских шаблонах**;  
- **экспортирует** с предпросмотром в форматы, нужные для учёбы и публикаций;  
- **опционально** открывает спектры во внешнем приложении (ChromaTsvet) и подтягивает литературу из Zotero/arXiv/DOI — но работает и полностью офлайн.

Цель — замкнуть цикл «материал → мысль → запись → отчёт» в одном приложении, а не заменить собой все существующие tools сразу.
