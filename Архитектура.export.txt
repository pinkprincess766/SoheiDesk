## 🏗️ Общая архитектура SoheiDesk

SoheiDesk — это **десктопное приложение** (Electron / Tauri) с бэкендом на Rust и фронтендом на Vue 3. Оно будет интегрироваться с ChromaTsvet (тоже на Rust) через IPC или HTTP.

---

### 📦 Основные компоненты (модули)

```
SoheiDesk
├── Бэкенд (Rust)
│   ├── Парсеры документов (PDF, DOCX, EPUB, MD, HTML, LaTeX, TXT)
│   ├── Индексатор и поисковик (Tantivy)
│   ├── Менеджер аннотаций и заметок (SQLite)
│   ├── Лабораторный журнал (SQLite)
│   ├── Конвертер (Typst, LaTeX, HTML, Markdown)
│   ├── Интеграции (Zotero, arXiv, DOI, PubMed)
│   ├── API-сервер (для фронтенда и ChromaTsvet)
│   └── Менеджер библиотек (каталог документов)
├── Фронтенд (Vue 3 + TypeScript)
│   ├── Ридер (отображение текста с аннотациями)
│   ├── Редактор (рисование, выделение, заметки)
│   ├── Лабораторный журнал (UI для записей)
│   ├── Поиск и фильтрация
│   ├── Панель интеграций
│   └── Настройки
└── Общее хранилище (SQLite)
    ├── Таблицы: документы, аннотации, заметки, журнал, теги, связи с спектрами
    └── Синхронизация с ChromaTsvet (общая БД или ссылки)
```

## 🧠 Детали каждого модуля

### 1. Бэкенд на Rust

#### a) Парсеры документов
- **Цель:** извлекать текст, структуру (заголовки, списки, таблицы) и метаданные из любых форматов.
- **Крейты:**
  - `pdf-extract` — для PDF.
  - `docx` — для DOCX.
  - `epub` — для EPUB.
  - `pulldown-cmark` — для Markdown.
  - `html2md` — для HTML (преобразование в Markdown для внутреннего использования).
  - `tex` — парсинг LaTeX через `latex2mathml` или свой лексер.
  - `encoding` — для определения кодировки TXT.
- **Результат:** структурированный объект (заголовки, параграфы, списки, таблицы) + plain text для индексации.

#### b) Индексатор и поисковик
- **Крейт:** `tantivy` — поисковый движок на Rust (как Elasticsearch, но встроенный).
- **Индексируемые поля:** текст, название, авторы, год, теги, аннотации.
- **Поиск:** полнотекстовый с поддержкой стемминга и морфологии (можно подключить русский и английский стеммеры).
- **Фильтры:** по дате, типу документа, тегам, наличию привязанных спектров.

#### c) Менеджер аннотаций и заметок
- **Хранилище:** SQLite (уже используется в ChromaTsvet, можно расширить или создать отдельную БД).
- **Сущности:**
  - `Annotation`: id, document_id, type (highlight/underline/comment/drawing), page/position, content, color, created_at.
  - `Note`: id, document_id, page, text, created_at, updated_at.
- **Связь с данными:** можно хранить ссылки на спектры (путь к файлу или идентификатор в ChromaTsvet).
- **Версионирование:** опционально, можно хранить историю изменений.

#### d) Лабораторный журнал
- **Сущности:**
  - `Entry`: id, title, content, date, tags, attachments (paths), linked_spectra (IDs), linked_documents (IDs).
  - `Template`: id, name, structure (JSON для полей).
  - `Tag`: id, name, color.
- **Функции:** CRUD, поиск по записям, экспорт в отчёт (через конвертер).
- **Хранилище:** SQLite.

#### e) Конвертер
- **Выходные форматы:** Typst, LaTeX, HTML, Markdown, DOCX.
- **Логика:**
  - Вход: структурированный документ + аннотации + выбранные записи журнала.
  - Генерация: используем шаблоны (например, для Typst — `typst` крейт для компиляции, но проще генерировать текстовый файл).
  - Для LaTeX: можно генерировать `.tex` с использованием `latex` крейта или самописного генератора.
  - Для HTML: использовать шаблонизатор (например, `tera`).
  - Поддержка вставки графиков (спектров) — генерировать изображения через ChromaTsvet и вставлять.
- **Интеграция с внешними утилитами:** можно вызывать `pandoc` как fallback.

#### f) Интеграции
- **Zotero / Mendeley:** через их API или локальную БД (SQLite) — импорт библиотеки и метаданных.
- **arXiv:** REST API — поиск, скачивание PDF и метаданных.
- **DOI:** через Crossref API — получение BibTeX и метаданных.
- **PubMed:** через E-utilities API.
- **RSS:** парсинг лент научных журналов для уведомлений.
- **Хранилище:** все импортированные документы сохраняются в локальной библиотеке с метаданными.

#### g) API-сервер
- **Протокол:** HTTP (можно использовать `axum` или `warp`) или IPC (сокеты).
- **Эндпоинты:**
  - `/documents` — CRUD документов.
  - `/annotations` — CRUD аннотаций.
  - `/journal` — CRUD записей.
  - `/search` — поиск.
  - `/convert` — конвертация.
  - `/integrations` — импорт из внешних источников.
  - `/open-spectrum` — открыть спектр в ChromaTsvet (запускает приложение или передаёт команду).
- **Аутентификация:** опционально, пока локальное приложение.

#### h) Менеджер библиотек
- **Структура:** каталог, где хранятся все документы (можно организовать как папку с файлами + SQLite для метаданных).
- **Автоматическое сканирование:** при добавлении новых файлов — парсинг и индексация.

### 2. Фронтенд (Vue 3)

#### a) Ридер (основное окно)
- **Компонент отображения текста:** используем `tiptap` (на основе ProseMirror) для рендеринга HTML с поддержкой аннотаций.
- **Поддержка слоёв:** текст + слой аннотаций (выделения, подчёркивания, рисунки) — можно использовать canvas для рисования поверх текста.
- **Навигация:** оглавление, переход по ссылкам, закладки.
- **Масштабирование и прокрутка.**

#### b) Редактор
- **Панель инструментов:** выделение, подчёркивание, зачёркивание, комментарий, рисование, вставка формулы.
- **Режимы:** выделение текста, рисование от руки, вставка фигур.
- **Интеграция с LaTeX:** всплывающее окно для ввода формул (с предпросмотром).

#### c) Лабораторный журнал
- **Список записей** с фильтрацией по тегам и дате.
- **Редактор записи** (рич-текст с поддержкой вложений и привязки спектров).
- **Кнопка «Создать отчёт»** — вызывает конвертер и экспортирует выбранные записи.

#### d) Поиск
- **Глобальный поиск** (по всем документам и журналу).
- **Расширенный поиск** с фильтрами.
- **Результаты** с контекстом и подсветкой.

#### e) Панель интеграций
- **Подключение Zotero/arXiv** — форма для ввода API-ключей или прямого импорта.
- **Отображение импортированных статей** в виде списка с возможностью добавить в библиотеку.

#### f) Настройки
- **Пути к библиотеке, ChromaTsvet.**
- **Настройки аннотаций** (цвета, шрифты).
- **Настройки экспорта** (шаблоны для Typst/LaTeX).

---

### 3. Хранилище данных (SQLite)

**Таблицы (основные):**

- `documents`: id, title, authors, year, journal, file_path, type (pdf/docx/...), added_date, metadata (JSON).
- `pages`: id, document_id, page_number, text_content (для поиска).
- `annotations`: id, document_id, page, type, position (JSON), content (текст комментария), color, created_at.
- `notes`: id, document_id, page, text, created_at, updated_at.
- `journal_entries`: id, title, content, date, tags (JSON), attachments (JSON), linked_spectra (JSON), linked_documents (JSON).
- `tags`: id, name, color.
- `integration_metadata`: id, source (zotero/arxiv/doi), external_id, data (JSON).
- `settings`: key, value.

**Связь с ChromaTsvet:** можно использовать общую БД или хранить пути к файлам спектров и вызывать ChromaTsvet через команду.

## 🔗 Взаимодействие с ChromaTsvet

- **Способ 1:** SoheiDesk вызывает ChromaTsvet как внешнее приложение с параметрами (путь к файлу, диапазон). Это просто: используем `std::process::Command` в Rust.
- **Способ 2:** ChromaTsvet предоставляет REST API (если реализовать), и SoheiDesk отправляет запросы на открытие спектра.
- **Синхронизация данных:** например, в лабораторном журнале хранятся ссылки на спектры — при клике открывается ChromaTsvet.

## 💡 Заметки по реализации

- **Производительность:** парсинг и индексация больших документов должны быть асинхронными, чтобы не блокировать UI.
- **Кроссплатформенность:** Tauri даёт нативные бинарники под Windows, macOS, Linux.
- **Безопасность:** все данные локальные, никаких облачных сервисов (по желанию пользователя).
- **Расширяемость:** архитектура модульная, легко добавлять новые парсеры или интеграции.
