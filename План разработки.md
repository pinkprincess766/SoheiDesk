## 1. Зафиксированный стек

### 1.1. Решение

| Слой | Выбор | Почему |
|------|--------|--------|
| Desktop shell | **Tauri 2** | Нативный вес, Rust-бэкенд, IPC, macOS/Windows/Linux |
| Backend | **Rust** (stable) | Парсинг, SQLite, поиск, файлы, `Command` |
| Frontend | **Vue 3 + TypeScript + Vite** | UI, TipTap/Milkdown |
| State | **Pinia** | Стандарт Vue 3 |
| Router | **Vue Router** | Reader, Journal, Library, Settings, Templates |
| БД | **SQLite** + **rusqlite** + migrations | Локальность |
| Поиск (этап 2+) | **Tantivy** | Full-text на Rust |
| Журнал / rich MD UI | **TipTap + Markdown extension** *или* **Milkdown** | Источник истины — **Markdown-строка**, не HTML |
| MD parse (Rust) | **pulldown-cmark** | Индекс, export, preview pipeline |
| PDF render | **pdf.js** (frontend) | Page mode |
| PDF text extract | **pdf-extract** / **lopdf** (Rust) | Не путать с рендером |
| TXT | `std` + **encoding_rs** | Кодировки |
| PDF-аннотации | Слой поверх pdf.js; **page-space** coords | Отдельный подэтап 1d |
| FS access (MVP) | **Только dialog / user-selected paths** | Без сканирования диска |
| Внешние apps | Опциональный launch **ChromaTsvet** через `Command` | Не hard dependency |
| Упаковка | Tauri bundler | dmg / msi / AppImage |
| JS packages | **pnpm** | |
| UI | **UnoCSS** или лёгкий **Tailwind** + свои компоненты | Без тяжёлого UI-kit |
| Тесты | **cargo test**, **Vitest** | |
| Линт | rustfmt, clippy, eslint, prettier | |
| Версии | SemVer `0.x` | `0.1.0` = MVP |

### 1.2. Markdown в журнале (принцип)

| Правило | Деталь |
|---------|--------|
| Storage | `journal_entries.body_md` и шаблоны — **всегда Markdown** (человекочитаемо, портативно) |
| Editor | TipTap с **Markdown-сериализацией** (`@tiptap/extension-markdown` или аналог) **либо Milkdown** (MD-native) |
| Не храним | HTML/JSON ProseMirror как primary source of truth |
| Export | Почти zero-cost: body уже MD; formatter только собирает frontmatter/поля/шапку |
| File MD viewer | MVP: **preview-first** (+ reflow-аннотации); in-place edit файла — nice-to-have |

Выбор между TipTap+MD extension и Milkdown — spike в начале Epic D (1–2 дня max); критерий: round-trip MD → editor → MD без потери простых конструкций (заголовки, списки, code, links).

### 1.3. Сознательно не берём (сейчас)

| Не берём | Причина |
|----------|---------|
| Electron | Лишний вес при Tauri + Rust |
| Общая БД с другими apps | Границы продуктов; только soft-launch |
| ORM (Diesel/SeaORM) на старте | Явный SQL + migrations |
| Pandoc hard dependency | Этап 3, optional |
| OCR | Этап 3+ |
| Cloud sync | Вне MVP |
| Сканирование всей FS | Security + Tauri scopes |
| Экспорт аннотаций в MD | **Этап 2** (не MVP) |

## 4. Этап 1 — MVP по подэтапам

### 4.0. Идентификация документов (сквозное правило)

| Правило | Реализация |
|---------|------------|
| **Primary key смысла** | `content_hash` — стабильный отпечаток содержимого |
| Алгоритм MVP | `SHA-256( file_size \|\| first N bytes \|\| last M bytes )` (N/M зафиксировать, напр. 64 KiB); при малых файлах — весь файл |
| **Path** | Вторичный: `last_path`, обновляется при успешном open |
| Open flow | 1) dialog → path 2) compute hash 3) если hash есть в БД — **восстановить** document_id, аннотации, last_path 4) иначе — новый document |
| Rename / move | Аннотации **не теряются**, если содержимое то же |
| Edit content | Новый hash → новый document **или** явный «это новая версия» (MVP: новый document + orphan old ann ок; version linking — later) |
| Path-only fallback | Если файл недоступен — запись в library с last_path и hash остаётся |

`documents.id` = UUID; уникальный индекс на `content_hash`.

### 4.3. Модель данных MVP

```sql
documents(
  id TEXT PRIMARY KEY,              -- UUID
  content_hash TEXT NOT NULL UNIQUE,
  title TEXT,
  last_path TEXT,                   -- secondary; may be stale
  doc_type TEXT NOT NULL,           -- pdf | md | txt
  file_size INTEGER,
  added_at TEXT NOT NULL,
  last_opened_at TEXT,
  metadata_json TEXT
);

annotations(
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES documents(id),
  ann_type TEXT NOT NULL,           -- highlight | comment
  page INTEGER,                     -- PDF page 0-based; NULL for reflow
  position_json TEXT NOT NULL,      -- page-space rects OR text offsets
  content TEXT,
  color TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

templates(
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  category TEXT,
  is_builtin INTEGER NOT NULL DEFAULT 0,
  fields_json TEXT NOT NULL,        -- schema, see §4.6
  body_md TEXT NOT NULL,
  default_tags_json TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

journal_entries(
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  template_id TEXT,                 -- may be null if template deleted
  body_md TEXT NOT NULL,            -- Markdown source of truth
  fields_json TEXT,                 -- { key: value }; unknown keys preserved
  tags_json TEXT,
  entry_date TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

settings(
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL               -- e.g. chroma_path, locale, theme
);
```

### 4.4. Поля шаблона (schema)

```json
{
  "key": "sample_id",
  "label": "Образец",
  "type": "text | number | date | tags | file | textarea",
  "required": true,
  "default": null
}
```

Тип `file` — path, выбранный через dialog (спектр, картинка, …).

---

### 4.5. Встроенные шаблоны (seed)

1. **Свободная заметка** — title + body  
2. **Протокол / синтез** — вещество, условия, процедура, результат, заметки  
3. **Измерение** — образец, прибор, параметры, файл спектра (`file`), результат, вывод  
4. **Конспект статьи** — citation, вопрос, тезисы, цитаты, follow-up  
5. **Еженедельный обзор** — цели, сделано, блокеры, план  

---

### 4.6. Валидация шаблонов и записей

| Когда | Что проверяем |
|-------|----------------|
| Save template | JSON schema полей: unique `key`, non-empty label, valid `type`; `body_md` — строка; builtin immutable (или fork) |
| Save / export entry | Все `required` поля заполнены (non-empty) |
| Template field removed | Старые ключи в `fields_json` **сохраняются** (не удалять данные); UI показывает «устаревшие поля» read-only или extra section |
| Template deleted | `template_id` остаётся или null; запись редактируема; required-check по последней известной schema snapshot (optional: store `template_snapshot_json` on entry at create — **рекомендуется в MVP**) |
| Invalid type value | number parse fail → error on field |

**Рекомендация MVP:** при создании записи копировать `template_snapshot_json` (fields schema + name), чтобы валидация и export не ломались при правке шаблона.

### 4.7. Критерии приёмки MVP

**Must (shippable / 1a+1b+1c):**

1. Open PDF, TXT, MD **через dialog** (без broad FS).  
2. Library + **content_hash**: rename → reopen → тот же document id.  
3. Journal entry from **builtin** and **custom** template; body stored as **Markdown**.  
4. Required-field validation on save.  
5. Export entry → MD + **preview before save**.  
6. Reflow highlight + comment persist across restart.  
7. `open_in_chroma` works when path configured; app works when not.  
8. Standalone app build runs.

**Should (full MVP / +1d):**

9. PDF highlight + comment in **page space**, correct under zoom, persist + restore.

**Won't (MVP):**

- Export annotations to MD → этап 2  
- Drawing, DOCX, Tantivy, OCR, cloud
